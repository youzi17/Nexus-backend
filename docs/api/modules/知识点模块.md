# 知识点模块 (M9 - KnowledgeModule)

> 知识点 CRUD、按天聚合查询、触发 AI 分析、分析记录管理

## 模块定位

- **职责边界**: 管理用户录入的知识点条目（增删查）、编排 AI 分析流程（查询知识点 → 可选联网搜索 → AI 流式分析 → 保存记录）、分析记录的存储与查询
- **不负责**: AI 模型调用细节（由 AiProcessingModule 负责）、联网搜索实现（由 SearchAggregatorModule 负责）
- **依赖模块**:
  - `AiProcessingModule` — 调用通义千问进行知识点分析，使用 `generateStream` 流式生成
  - `SearchAggregatorModule` — 可选联网搜索，为分析提供外部资料增强
- **被依赖**: 无（顶层业务模块）

## 数据模型

| 实体 | 文件路径 | 说明 |
|------|---------|------|
| `KnowledgeEntry` | `entities/knowledge-entry.entity.ts` | 知识点条目，支持软删除（`@DeleteDateColumn`），复合索引 `idx_ke_user_created` |
| `AnalysisRecord` | `entities/analysis-record.entity.ts` | 分析记录，含状态流转（pending→processing→completed/failed）、token 统计，复合索引 `idx_ar_user_date` |

详细字段设计见 `docs/数据库设计.md`

## 接口概览

### 知识点 CRUD（KnowledgeEntryController）

| 方法 | 路径 | 说明 | 认证 |
|------|------|------|------|
| POST | `/knowledge` | 创建单条知识点 | 需要 |
| POST | `/knowledge/batch` | 批量创建知识点 | 需要 |
| GET | `/knowledge?date=YYYY-MM-DD` | 按天查询知识点列表（默认今天） | 需要 |
| DELETE | `/knowledge/:id` | 软删除知识点（校验所属权） | 需要 |

### 分析功能（KnowledgeAnalysisController）

| 方法 | 路径 | 说明 | 认证 |
|------|------|------|------|
| POST | `/knowledge/analyze` | 触发 AI 分析（SSE 流式响应） | 需要 |
| GET | `/knowledge/analysis-history` | 查询历史分析记录（最近 50 条） | 需要 |

接口详细参数和响应格式见 `docs/接口文档.md` 第 2 节

## 核心业务逻辑

### 分析流程（SSE 流式）

```
POST /knowledge/analyze { date, webSearchEnabled }
    ↓
查询当天所有知识点（无知识点则 400 报错）
    ↓
创建 AnalysisRecord（status: processing）
    ↓
（可选）联网搜索：提取前 3 条知识点关键内容作为搜索词，失败不阻塞
    ↓
PromptTemplateService 构建 knowledge-analysis 提示词
    ↓
AiProcessingService.generateStream 流式生成
    ↓ SSE 事件透传给前端
完成时更新 AnalysisRecord（status: completed, resultContent, tokenUsage）
失败时更新 AnalysisRecord（status: failed, errorMessage）
```

### 业务规则

- 知识点内容最大 5000 字，标签为可选字符串数组
- 按天查询基于 `createdAt` 字段的本地日界时间范围（00:00:00 ~ 23:59:59.999）
- 删除操作为软删除，校验知识点所属权（非本人返回 403）
- 同一用户同一天可多次分析（不做唯一约束）
- 联网搜索为辅助功能，失败时静默降级（返回空结果，不阻塞 AI 分析）

## 模块协作

- **与 AiProcessingModule**: 通过 `AiProcessingService.generateStream()` 调用，传入已构建好的提示词（`skipPromptBuild: true`），接收 `AsyncIterable<StreamEvent>` 流式事件
- **与 SearchAggregatorModule**: 通过 `SearchAggregatorService.aggregateSearch()` 调用，搜索结果融入提示词上下文
- **异常处理**: 联网搜索失败不影响核心分析流程；AI 调用失败会更新记录状态为 failed 并通过 SSE error 事件通知前端

## 文件结构

```
src/modules/knowledge/
├── dto/
│   ├── analyze-request.dto.ts          # 分析请求参数
│   ├── create-knowledge-entry.dto.ts   # 创建知识点参数（含批量）
│   └── knowledge-query.dto.ts          # 按天查询参数
├── entities/
│   ├── analysis-record.entity.ts       # 分析记录实体 + TokenUsage 接口
│   └── knowledge-entry.entity.ts       # 知识点条目实体（软删除）
├── knowledge.module.ts                 # 模块定义，导入 AI 和搜索聚合模块
├── knowledge-analysis.controller.ts    # 分析接口（SSE + 记录查询）
├── knowledge-analysis.service.ts       # 分析编排服务
├── knowledge-entry.controller.ts       # 知识点 CRUD 接口
└── knowledge-entry.service.ts          # 知识点数据操作服务
```

## 注意事项

- **SSE 实现**: Controller 使用 `POST + text/event-stream`，将 `AsyncIterable<StreamEvent>` 转为 `Observable<MessageEvent>`
- **提示词模板**: 使用 `knowledge-analysis` 模板类型，模板文件位于 `ai-processing/prompts/templates/knowledge-analysis.template.ts`
- **时区问题**: 前端传入的 date 参数为 YYYY-MM-DD，服务端按本地日界时间范围查询
