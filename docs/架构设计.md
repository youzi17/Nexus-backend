
# 项目架构设计

**项目名称**：FlowGenAll - 知识点聚合分析系统
**技术栈**：Vue 3 + NestJS + PostgreSQL + Redis + 阿里云通义千问
**设计原则**：KISS - 只做核心必须的功能

> **v2.0 改造说明（2026-02-25）**：系统从"多模态智能搜索引擎"改造为"知识点聚合分析系统"。
> 详细改造计划见 `docs/知识点聚合分析系统改造计划.md`。

---

## 项目定位

构建一个知识点聚合分析系统，用户随时录入知识点（文字），系统按天聚合，点击分析时由 AI 对当天知识点进行分类整理、关联关系分析和逻辑脉络梳理，支持可选联网搜索增强，结果以结构化 Markdown 文字呈现。

**核心优势**：全面采用国产、低成本、高性能的阿里云通义千问模型，显著降低 AI 调用成本，满足中文场景下的高精度理解与生成需求。

### 架构分层说明

**前端层**：
- 负责用户交互、数据展示、状态管理
- 使用 Vue 3 Composition API + TypeScript + Pinia
- UI 组件库：Naive UI（轻量、TypeScript 友好）

**后端层**：
- 业务逻辑处理、数据持久化、第三方服务集成
- 使用 NestJS + TypeORM + TypeScript
- 提供 RESTful API 和 SSE 流式接口

**基础设施层**：
- 数据存储：PostgreSQL（关系数据）+ Redis（缓存）
- AI 服务：阿里云通义千问（Qwen-Plus/Qwen-Max）
- 外部服务：联网搜索聚合（可选增强）

## 核心模块

### M1 - 用户认证模块
- **职责**：用户注册、登录、登出，JWT 认证和 Token 刷新
- **实现位置**：`src/modules/auth/`
- **核心技术**：JWT + bcrypt + Passport
- **详细文档**：`docs/api/modules/用户认证模块.md`

### M3 - 外部数据聚合模块
- **职责**：可选联网搜索，为 AI 分析提供外部资料增强
- **实现位置**：`src/modules/search-aggregator/`
- **核心技术**：HTTP Client + Redis 缓存
- **详细文档**：`docs/api/modules/外部数据聚合模块.md`

### M4 - AI 处理模块
- **职责**：调用阿里云通义千问进行知识点分类、关联分析和逻辑梳理
- **实现位置**：`src/modules/ai-processing/`
- **核心技术**：阿里云 DashScope SDK + 提示词工程
- **模型选择**：
  - Qwen-Plus：默认模型，成本低、速度快
  - Qwen-Max：知识点数量多或内容复杂时自动升级
- **详细文档**：`docs/api/modules/AI处理模块.md`

### M9 - 知识点模块（新）
- **职责**：知识点 CRUD、按天查询、触发 AI 分析、分析记录管理
- **实现位置**：`src/modules/knowledge/`
- **核心技术**：SSE 流式输出 + AiProcessingService + SearchAggregatorService
- **详细文档**：`docs/api/modules/知识点模块.md`

## 数据库设计

### 核心表结构

**users** - 用户表
- 主键：id (UUID)
- 关键字段：username, email, password_hash, preferences (JSONB)
- 关联：一对多 knowledge_entries、一对多 analysis_records

**knowledge_entries** - 知识点条目表
- 主键：id (UUID)
- 关键字段：content (text), tags (JSONB), userId
- 索引：userId, createdAt（按天查询核心索引）

**analysis_records** - 分析记录表
- 主键：id (UUID)
- 关键字段：date, knowledgeEntryIds (JSONB), resultContent, webSearchEnabled, status, tokenUsage
- 索引：userId, date

### 表关系图

```
users (1) ──────< (N) knowledge_entries
  │
  └───────< (N) analysis_records
```

**详细设计**：见 `docs/数据库设计.md`

## 核心业务流程

### 1. 知识点录入流程

```
用户输入知识点文字（单条或批量粘贴）
    ↓
POST /api/knowledge
    ↓
保存到 knowledge_entries 表（带 createdAt 时间戳）
    ↓
返回创建成功
```

### 2. 知识点分析流程（核心）

```
用户选择日期（默认今天），点击"分析"
    ↓
POST /api/knowledge/analyze { date, webSearchEnabled }
    ↓
查询当天所有知识点
    ↓
（可选）联网搜索相关资料（10s 超时，失败不阻塞）
    ↓
构建分析提示词：知识点列表 + 外部资料
    ↓
调用通义千问（SSE 流式输出）：
    event: start   → 任务开始（taskId/model/startTime）
    event: chunk   → AI 生成内容片段
    event: done    → 完成，返回 token 统计
    ↓
保存分析记录到 analysis_records 表
```

### 3. 用户认证流程

```
用户注册/登录
    ↓
密码 bcrypt 加密（work factor = 10）
    ↓
生成 JWT Token（access_token 默认 15m，可由 JWT_EXPIRES_IN 配置；refresh_token 默认 7d）
    ↓
后续请求携带 Token（Authorization: Bearer <token>）
    ↓
JWT 守卫验证 Token → 注入 user 信息到 request
```

## 性能优化策略

### 缓存策略
- **AI 分析结果**：相同日期 + 相同知识点内容缓存 1 小时（降低成本）
- **联网搜索结果**：Redis 缓存 1 小时（减少 API 调用）

### 成本控制
- **模型选择**：优先使用 qwen-plus，知识点超过 20 条或内容超过 2000 字时升级到 qwen-max
- **联网搜索**：用户主动开启才调用，默认关闭

## 安全设计

### 认证与授权
- **密码加密**：bcrypt（work factor = 10）
- **JWT 认证**：access_token + refresh_token
- **权限控制**：用户只能访问自己的知识点和分析记录

### 数据安全
- **SQL 注入防护**：TypeORM 参数化查询
- **XSS 防护**：前端输入过滤、后端输出转义
