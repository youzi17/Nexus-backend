# 知识点聚合分析系统改造计划

> **状态：已完成（2026-02-25）** — 所有阶段均已实施，旧模块已清理，新模块已上线。

**文档版本**：v1.0
**创建日期**：2026-02-25
**完成日期**：2026-02-25

---

## 一、改造背景

原系统定位为"多模态智能搜索引擎"，核心功能是文件上传 + 多源聚合搜索 + AI 整合输出。
本次改造将系统重新定位为**知识点聚合分析系统**，聚焦于用户日常知识点的录入、管理与 AI 深度分析。

---

## 二、新系统定位

用户随时录入知识点（文字），系统按天聚合，点击分析时由 AI 对当天知识点进行：
- **分类整理**：识别知识点所属领域/主题
- **关联关系分析**：发现知识点之间的逻辑联系
- **逻辑脉络梳理**：输出有条理的结构化文字（含关系描述）

支持可选联网搜索，用外部资料增强分析深度。

## 三、模块改造策略

### 删除模块

| 模块 | 原因 |
|------|------|
| M2 - FilesModule（文件管理） | 不再需要文件上传，知识点以纯文字录入 |
| WorkflowsModule（工作流） | 与新功能无关 |
| M8 - ExportModule（导出服务） | 暂不需要 |
| M5 - SearchModule（搜索服务） | 被新的 KnowledgeModule 替代 |
| M6 - SearchHistoryModule（搜索记录） | 分析记录内置到 KnowledgeModule |

### 保留模块

| 模块 | 改动 |
|------|------|
| M1 - AuthModule（用户认证） | 不变 |
| UsersModule（用户管理） | 不变 |
| M3 - SearchAggregatorModule（外部数据聚合） | 不变，复用联网搜索能力 |
| M4 - AiProcessingModule（AI 处理） | 新增知识点分析提示词模板 |

### 新增模块

| 模块 | 职责 |
|------|------|
| **KnowledgeModule（知识点模块）** | 知识点 CRUD + 按天分析 + 分析记录管理 |

## 四、实施阶段

### Stage 1：数据层
**目标**：建立新数据模型

新增实体：
- `KnowledgeEntry`（知识点条目）：id, content, tags, userId, createdAt
- `AnalysisRecord`（分析记录）：id, date, knowledgeEntryIds, resultContent, webSearchEnabled, tokenUsage, status, userId

### Stage 2：知识点 CRUD
**目标**：知识点的增删查接口

接口：
- `POST /api/knowledge` - 创建知识点（支持单条/批量）
- `GET /api/knowledge?date=YYYY-MM-DD` - 按天查询
- `DELETE /api/knowledge/:id` - 删除知识点

### Stage 3：AI 分析提示词
**目标**：新增知识点聚合分析专用提示词模板

提示词引导 AI 输出：
- 知识点分类（按主题/领域归组）
- 关联关系（哪些知识点相互关联、如何关联）
- 逻辑脉络（整体知识结构的文字描述）

### Stage 4：分析服务（核心）
**目标**：按天分析知识点，SSE 流式输出

接口：
- `POST /api/knowledge/analyze` - 触发分析（参数：date、webSearchEnabled）
- `GET /api/knowledge/analysis-history` - 历史分析列表
- `GET /api/knowledge/analysis/:id` - 单条分析结果

流程：
```
查询当天知识点
    ↓
（可选）联网搜索相关资料
    ↓
AI 分析：分类 + 关联关系 + 逻辑脉络
    ↓
SSE 流式返回分析进度和结果
    ↓
保存分析记录
```

### Stage 5：清理旧模块 & 更新文档
**目标**：移除废弃模块，确保编译通过，更新所有文档

## 六、新数据库表结构

**knowledge_entries**（知识点条目表）
- id (UUID, PK)
- content (text) - 知识点内容
- tags (jsonb, default []) - 用户标签
- userId (uuid, FK → users)
- createdAt (timestamp) - 按天查询的核心字段
- updatedAt (timestamp)

**analysis_records**（分析记录表）
- id (UUID, PK)
- date (date) - 分析的日期
- knowledgeEntryIds (jsonb) - 参与分析的知识点 ID 列表
- resultContent (text) - AI 分析结果（Markdown）
- webSearchEnabled (boolean) - 是否启用了联网搜索
- status (enum: pending/processing/completed/failed)
- tokenUsage (jsonb) - token 消耗统计
- processingTimeMs (int)
- errorMessage (text, nullable)
- userId (uuid, FK → users)
- createdAt (timestamp)
- updatedAt (timestamp)

## 七、风险与应对

| 风险 | 应对 |
|------|------|
| 旧模块间存在交叉依赖 | Stage 5 前先全局检索所有 import，统一清理 |
| AI 分析结果过长导致 SSE 超时 | 使用真正的流式生成（generateStream），非模拟分块 |
| 联网搜索失败影响分析 | 沿用现有 10s 超时机制，失败不阻塞 AI 分析 |
| TypeORM synchronize 建表顺序 | 确保外键依赖顺序正确，User 表先于 knowledge 表 |
