# 数据库设计文档

**项目**: FlowGenAll - 知识点聚合分析系统
**技术栈**: PostgreSQL + TypeORM（synchronize 模式）
**设计原则**: KISS - 只保留核心必要功能

---

## 1. 数据库表结构

### 1.1 users - 用户表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | UUID | PRIMARY KEY | 用户唯一标识 |
| username | VARCHAR(50) | UNIQUE, NOT NULL | 用户名 |
| email | VARCHAR(100) | UNIQUE, NOT NULL | 邮箱 |
| password_hash | VARCHAR(255) | NOT NULL | 密码哈希值（bcrypt） |
| avatar_url | VARCHAR(500) | NULL | 头像URL |
| preferences | JSONB | DEFAULT '{}' | 用户偏好设置 |
| role | ENUM('user','advanced','admin') | DEFAULT 'user' | 用户角色 |
| created_at | TIMESTAMP | NOT NULL | 创建时间 |
| updated_at | TIMESTAMP | NOT NULL | 更新时间 |

**索引**:
- `idx_users_email` ON (email) UNIQUE
- `idx_users_username` ON (username) UNIQUE

**说明**:
- 采用 UUID 作为主键，便于分布式扩展
- role 枚举：user（普通用户）、advanced（高级用户）、admin（管理员）

---

### 1.2 knowledge_entries - 知识点条目表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | UUID | PRIMARY KEY | 知识点唯一标识 |
| content | TEXT | NOT NULL | 知识点内容（纯文字，最大 5000 字） |
| tags | JSONB | DEFAULT '[]' | 用户自定义标签 |
| user_id | UUID | FK(users.id), NOT NULL | 所属用户 |
| deleted_at | TIMESTAMP | NULL | 软删除时间戳 |
| created_at | TIMESTAMP | NOT NULL | 创建时间（按天查询的核心字段） |
| updated_at | TIMESTAMP | NOT NULL | 更新时间 |

**索引**:
- `idx_ke_user_created` ON (user_id, created_at) — 复合索引，按用户+时间查询（高频场景）

**外键**:
- `FK` user_id → users(id)

**说明**:
- 使用 TypeORM 的 `@DeleteDateColumn` 实现软删除，删除后 `deleted_at` 自动填充时间戳
- tags 示例：`["TypeScript", "泛型", "前端"]`
- 按天查询是核心场景，复合索引覆盖 userId + createdAt

---

### 1.3 analysis_records - 分析记录表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | UUID | PRIMARY KEY | 分析记录唯一标识 |
| date | DATE | NOT NULL | 分析的目标日期 |
| knowledge_entry_ids | JSONB | DEFAULT '[]' | 参与分析的知识点 ID 列表 |
| result_content | TEXT | NULL | AI 分析结果（Markdown 格式） |
| web_search_enabled | BOOLEAN | DEFAULT false | 是否启用了联网搜索 |
| status | ENUM('pending','processing','completed','failed') | DEFAULT 'pending' | 分析状态 |
| token_usage | JSONB | NULL | Token 消耗统计 |
| processing_time_ms | INTEGER | NULL | 处理耗时（毫秒） |
| error_message | TEXT | NULL | 错误信息（失败时） |
| user_id | UUID | FK(users.id), NOT NULL | 所属用户 |
| created_at | TIMESTAMP | NOT NULL | 创建时间 |
| updated_at | TIMESTAMP | NOT NULL | 更新时间 |

**索引**:
- `idx_ar_user_date` ON (user_id, date) — 复合索引，按用户+日期查询（高频场景）

**外键**:
- `FK` user_id → users(id)

**说明**:
- status 状态流转：`pending → processing → completed/failed`
- token_usage 示例：`{"inputTokens": 1500, "outputTokens": 800, "totalCost": 0.023}`
- knowledge_entry_ids 示例：`["uuid-1", "uuid-2", "uuid-3"]`
- 同一用户同一天可以多次分析（不做唯一约束）

---

### 1.4 search_source_configs - 外部数据源配置表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | UUID | PRIMARY KEY | 配置唯一标识 |
| name | VARCHAR(255) | UNIQUE, NOT NULL | 数据源名称（baidu-search/wikipedia） |
| description | VARCHAR(255) | NOT NULL | 数据源描述 |
| enabled | BOOLEAN | DEFAULT true | 是否启用 |
| priority | INTEGER | DEFAULT 0 | 优先级（数值越大优先级越高） |
| rate_limit | INTEGER | DEFAULT 100 | 每分钟请求限制 |
| config | JSONB | NULL | 配置信息（apiKey、baseUrl、timeout 等） |
| created_at | TIMESTAMP | NOT NULL | 创建时间 |
| updated_at | TIMESTAMP | NOT NULL | 更新时间 |

**索引**:
- `idx_search_source_configs_name` ON (name) UNIQUE
- `idx_search_source_configs_enabled` ON (enabled)
- `idx_search_source_configs_priority` ON (priority)

**说明**:
- 用于配置联网搜索的外部数据源（SearchAggregatorModule 使用）
- config 示例：`{"apiKey": "xxx", "baseUrl": "https://api.example.com", "timeout": 5000}`

## 2. 表关系图

```
users (1) ──────< (N) knowledge_entries
  │
  └───────< (N) analysis_records

search_source_configs (独立表，无外键关联)
```

**关系说明**:
- 一个用户可以录入多条知识点
- 一个用户可以有多条分析记录
- search_source_configs 是独立的配置表，不与其他表关联

## 3. 数据库配置

### 3.1 TypeORM 配置

```
synchronize: true  // 自动同步实体到数据库，无需 migration
```

### 3.2 PostgreSQL 扩展

```sql
-- 启用 UUID 扩展
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
```

---

## 4. 数据安全

### 4.1 数据加密
- 密码使用 bcrypt 哈希（work factor >= 10）
- 敏感配置存储在环境变量中

### 4.2 软删除策略
- knowledge_entries 使用 `deleted_at` 字段实现软删除
- 软删除的数据不会出现在常规查询中（TypeORM 自动过滤）

### 4.3 备份策略
- 每日全量备份
- 每小时增量备份
- 保留最近 7 天备份

---

## 5. 性能优化

### 5.1 索引设计
- 所有高频查询场景均有复合索引覆盖
- `idx_ke_user_created`: 知识点按天查询
- `idx_ar_user_date`: 分析记录按日期查询

### 5.2 缓存策略
- Redis 缓存 AI 分析结果（TTL 1 小时）
- Redis 缓存联网搜索结果（TTL 1 小时）
